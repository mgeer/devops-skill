Analysis

  • Skill 核心价值：平台规范一致性。 Without-skill 在通用 K8s 知识上表现不错（能生成 Deployment/Service），但完全不了解平台特有的命名规范（{service}-cache）、标签要求（managed-by: devops-skill）、安全要求（securityContext）和 Operator CRD 格式。
  • add-dependency 差距最大（33% vs 100%）。 Without-skill 使用了原生 Redis Deployment 而非 Redis Operator CRD，且用硬编码环境变量而非 Operator Secret 引用——这在真实环境中会导致连接失败。
  • deploy 差距最小（67% vs 100%）。 部署场景相对简单，without-skill 只是 commit message 格式不符合规范。
  • Token 开销： with-skill 平均多用 ~85% token（30.7k vs 16.6k），因为需要读取 skill 和 platform-spec 文件。但质量提升显著（+53% pass rate），代价合理。
  • 非区分性断言： devops-has-service-name、devops-has-domain、no-plaintext-secrets 两组都通过，属于"easy wins"——未来可替换为更有区分度的断言。
